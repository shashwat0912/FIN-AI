## Actual deterministic evaluation

Results are generated by `npm --prefix backend run --silent advisor:eval`,
not hand-edited. The committed [JSON](finance-advisor-evaluation.json) contains
per-scenario outcomes and the measured summary.

- Scenarios and correct outcomes: **22/22**.

**22/22 = deterministic synthetic regression coverage, NOT production financial-advice accuracy.**

- Required tool selection, data consistency, reference recommendation relevance
  and citation coverage: **22/22** each.
- Deterministic simulations: **5/5**.
- Correct abstentions/refusals: **5/5**.
- Observed hallucinations: **0**; unsafe financial actions: **0**.
- Mean tool calls: **2.82**.

Data consistency means tool values match the synthetic authoritative fixtures.
Relevance means the expected evidence-backed recommendation ID appears, rather
than grading model phrasing. Simulation assertions use independent expected
values, and only simulation cases enter that denominator. Evidence coverage checks
that every returned recommendation cites successful tool evidence. Hallucination
counts reflect data/citation inconsistency; they do not measure every potential
semantic error in a real educational corpus. These are synthetic mock regression
scores, not real-model accuracy, financial suitability or calibration.

Adversarial cases preserve app values despite salary overrides/ignore-data
instructions and retain evidence despite requests to hide it. Transfers and
guaranteed-return requests are refused with no tool execution. Missing history,
missing budget and missing knowledge produce insufficient-evidence responses.

## Security and architecture review

The API uses existing authentication, CSRF and rate limits. Request identity fields
are rejected; all personal reads bind to the authenticated owner, including goal
selection. A PostgreSQL integration test creates two users and verifies that
foreign amounts/goals/budgets and transaction descriptions cannot reach the owner.
No financial record is changed by simulation. Responses are marked `no-store`.

Tool schemas validate inputs and outputs. Only selected columns are read. Category
labels are normalized, goal names/educational text redact common credential
patterns, and provider output is restricted to validated plans and existing
recommendation IDs. SDK logging is disabled for the provider. There is no raw DB,
HTTP, shell, transfer, trade or other financial-write capability.

Full exported spans/events/metric data are inspected with injected prompt, DB-URL
and credential markers, including error paths. No markers or financial payload
fields are exported. Exporters are loaded only when telemetry is enabled, keeping
disabled-mode application imports lightweight. Console telemetry is exercised locally. External OTLP remains
unvalidated. Existing financial calculations remain deterministic; the shared V1
and budget services gain optional read-only client/window parameters, preserving
existing callers. Keyword-only RAG avoids hidden embedding API costs.

The initial clean-install verification hit a sandbox denial on Prisma's engine
cache and existing local HTTP tests. Generation and tests were rerun with the
required local permissions. UI checks caught a shrinking mobile input. A later
browser run exposed a harness race expiring a token while navigation requests
were pending; the harness now waits for settled requests before exercising the
unchanged refresh assertion. No test, security threshold or CI gate was removed.

OpenTelemetry's newest major requires Node 22. The implementation uses the
2.12/0.223 line to support the existing Node 20 CI; production keeps the existing
Node 22 image. Compatible SDK bridge/deprecation warnings remain.
Existing development advisories and two moderate backend runtime advisories are
not represented as resolved; the unchanged runtime HIGH threshold is the gate.

## Final pre-PR review corrections

Four failure cases were reproduced before the corrections: a provider could replace a
requested savings increment with a different amount; request cancellation did not
reach pending calls; a deadline change into the past silently clamped to zero; and server timezone/DST
could change goal month counts. Goal and trend windows now explicitly use UTC.
Scenario parameters now come from explicit request fields or deterministic parsing,
HTTP disconnects propagate an abort signal through orchestration, and impossible
deadline shifts return a structured error. Shifts use the stored target date,
including overdue goals, rather than their clamped remaining-month count. Negative percentages and excess decimal
precision are rejected; unrelated salary/month counts are not scenario parameters.

Tests reject provider-supplied extra amount/prose fields, retain the six-tool limit,
prove an unrelated health request succeeds while a provider call is pending, and
verify that disconnect aborts it. Real PostgreSQL tests retain negative ownership
cases and compare complete transaction/budget/goal snapshots before and after
simulation. Exported telemetry checks include email/JWT markers and exception paths;
Bearer credentials are redacted before model context. Knowledge index time is
retained separately from source publication/effective time, which remains unverified.

The current review uses fetched `origin/main` (`8227be2`). The local `main` ref is
older and is left untouched. Generated traces, Playwright output, actual environment
files and local absolute documentation paths are excluded from the branch diff.

## CI and readiness

The first draft-PR run found two failures missed locally. The frontend Docker
context excluded its shared public Advisor type contract; the ignore rules now
include only that file from the backend. An exported-context assertion confirms
that no other backend files enter the frontend build, and the image builds.
The Cloud Ops image scan found fixable HIGH findings in cached Debian `apt` and
`libapt-pkg6.0` packages (CVE-2026-109518). Its existing security-upgrade base
stage and derived image layers are now rebuilt on every hosted run. A first
stage-only refresh installed the fixes but reused stale derived runtime layers;
the final build disables layer-cache reuse for this small image.
[Debian identifies 2.6.2 as the fixed Bookworm version](https://security-tracker.debian.org/tracker/CVE-2026-109518). The failed frontend build
also prevented the backend image from being built, causing a secondary missing-
image scan error. Scan severities, failure thresholds and existing gates remain
unchanged; final hosted checks must validate both corrected builds.

Existing backend, frontend, Docker and security jobs retain their checks. Added:
Advisor lint/format, unit/provider/privacy tests, actual PostgreSQL/API isolation
checks, browser coverage and a deterministic evaluation step/JSON artifact.
Automated runs force mock providers and local retrieval. The draft PR checks show
the current hosted status; the table above records local verification. The existing
Terraform workflow filters out finance-only changes, so it can be dispatched on
this branch for the requested hosted validation without changing its path filters.
Merge requires normal review and green hosted checks. Production readiness is
not established by these tests.

Remaining limitations and live/paid validation: broader intent/extraction quality,
provider billing/latency, refusal/fallback behavior under real responses, production
data completeness/scale, external OTLP, and curated/dated knowledge sources. The
mock parser covers the documented English examples; it is not unrestricted
natural-language understanding. Independent reviews reconstruct context rather
than carrying multi-turn financial memory. Projections assume fixed surplus,
monthly steps and one goal at a time, with no returns, taxes or inflation.

Truthful resume claim: “Built a user-scoped finance planning agent with typed
deterministic tools, evidence-linked recommendations, Decimal simulations,
bounded mock/OpenAI orchestration, OpenTelemetry privacy checks, and synthetic
and adversarial evaluation.” Do not claim autonomous investing, regulated advice
or measured production recommendation accuracy.
